## 2. 编译整个源码

所有编译都从 SDK 根目录执行 `./build.sh`。

### 2.1 命令行模式

```bash
cd /home/whd/experiment/rk3568_linux_5.10_20250211/rk3568_linux_5.10

# 单独编译内核
./build.sh kernel

# 单独编译 uboot
./build.sh uboot

# 编译完整固件（uboot + kernel + rootfs + recovery → 统一镜像）
./build.sh all

# 打包固件
./build.sh firmware

./build.sh updateimg

./build.sh cleanall
```

# Ubuntu 20.04 根文件系统

./build.sh ubuntu20_update    # 只更新 rootfs

# Ubuntu 22.04 / Debian 10 / Debian 11 同理
./build.sh ubuntu22
./build.sh debian10
./build.sh debian11
```

不带参数直接运行，会弹出菜单选择：

```

## 3. 编译自定义内核模块 (.ko) 并测试

以 `beep.c`（蜂鸣器驱动）为例，走通从源码到板子验证的完整流程。

### 3.1 编写驱动代码

在 `kernel/drivers/misc/` 下创建 `beep.c`：

```c
#include <linux/init.h>
#include <linux/module.h>
#include <linux/miscdevice.h>
#include <linux/fs.h>
#include <linux/uaccess.h>
#include <linux/io.h>
#include <linux/kernel.h>

#define GPIO5_DR 0x020AC000
unsigned int *vir_gpio5_dr;

ssize_t misc_read(struct file *file, char __user *ubuf, size_t size, loff_t *loff_t)
{
    printk("misc_read\n");
    return 0;
}

ssize_t misc_write(struct file *file, const char __user *ubuf, size_t size, loff_t *loff_t)
{
    char kbuf[64] = {0};
    if (copy_from_user(kbuf, ubuf, size) != 0) {
        printk("copy_from_user error\n");
        return -1;
    }
    printk("kbuf is %d\n", kbuf[0]);
    if (kbuf[0] == 1)
        *vir_gpio5_dr |= (1 << 1);      // 置位 bit1 → 开蜂鸣器
    else if (kbuf[0] == 0)
        *vir_gpio5_dr &= ~(1 << 1);     // 清零 bit1 → 关蜂鸣器
    return 0;
}

int misc_release(struct inode *inode, struct file *file)
{
    printk("hello misc_release bye bye\n");
    return 0;
}

int misc_open(struct inode *inode, struct file *file)
{
    printk("hello misc_open\n");
    return 0;
}

struct file_operations misc_fops = {
    .owner   = THIS_MODULE,
    .open    = misc_open,
    .release = misc_release,
    .read    = misc_read,
    .write   = misc_write,
};

struct miscdevice misc_dev = {
    .minor = MISC_DYNAMIC_MINOR,
    .name  = "hello_misc",          // 设备节点名 /dev/hello_misc
    .fops  = &misc_fops,
};

static int __init misc_init(void)
{
    int ret;
    ret = misc_register(&misc_dev);
    if (ret < 0) {
        printk("misc register error\n");
        return ret;
    }
    printk("misc register succeed\n");

    vir_gpio5_dr = ioremap(GPIO5_DR, 4);
    if (vir_gpio5_dr == NULL) {
        printk("GPIO5_DR ioremap error\n");
        return -EBUSY;
    }
    printk("GPIO5_DR ioremap ok\n");
    return 0;
}

static void __exit misc_exit(void)
{
    misc_deregister(&misc_dev);
    iounmap(vir_gpio5_dr);
    printk("misc goodbye!\n");
}

module_init(misc_init);
module_exit(misc_exit);
MODULE_LICENSE("GPL");
```

### 3.2 修改 Kconfig（添加配置选项）

编辑 `kernel/drivers/misc/Kconfig`，在文件末尾添加：

```kconfig
config BEEP
    tristate "Beep driver for RK3568"
    depends on ARCH_ROCKCHIP
    help
      This is a test beep driver for iTOP-RK3568 board.
      If unsure, say N.
```

### 3.3 修改 Makefile（添加编译规则）

编辑 `kernel/drivers/misc/Makefile`，在文件末尾添加：

```makefile
obj-$(CONFIG_BEEP) += beep.o
```

### 3.4 启用驱动配置

有两种方式：直接编辑 defconfig（快速），或者用 menuconfig（直观）。

#### 方式 A：直接编辑 defconfig（推荐，简单直接）

编辑内核配置文件 `kernel/arch/arm64/configs/rockchip_linux_defconfig`，添加：

```
CONFIG_BEEP=m
```

| 值 | 含义 | menuconfig 显示 |
|----|------|----------------|
| `=y` | 编译进内核镜像，开机自动生效 | `[*]` |
| `=m` | 编译为独立模块 (.ko)，需手动 insmod | `[M]` |
| `=n` | 不编译 | `[ ]` |

#### 方式 B：使用 menuconfig（图形界面配置）

menuconfig 是内核自带的终端图形配置工具，可以浏览、搜索、修改所有内核选项。

**启动 menuconfig：**

```bash
cd /home/whd/experiment/rk3568_linux_5.10_20250211/rk3568_linux_5.10/kernel

# 先用当前 defconfig 生成 .config，然后启动 menuconfig
make ARCH=arm64 rockchip_linux_defconfig    # 生成 .config
make ARCH=arm64 menuconfig                  # 启动图形界面
```

**基本操作：**

| 按键 | 作用 |
|------|------|
| `↑ ↓` | 上下移动 |
| `← →` | 切换底部按钮（Select / Exit / Help / Save） |
| `Enter` | 进入子菜单 / 确认 |
| `空格` | 切换编译状态：`[ ]`(不编) → `[*]`(编入内核) → `[M]`(模块) |
| `Y` | 快捷设为 `[*]`（编入内核） |
| `M` | 快捷设为 `[M]`（模块） |
| `N` | 快捷设为 `[ ]`（不编译） |
| `/` | **搜索**，输入关键词查找配置项 |
| `?` | 显示当前选项的帮助信息 |
| `Tab` | 切换焦点 |
| `Esc` 两次 | 返回上级 / 退出 |

**搜索示例 — 找到 BEEP 配置项：**

```
按 / → 输入 "BEEP" → Enter
```

搜索结果会显示：

```
Symbol: BEEP
  Type  : tristate
  Prompt: BEEP Test
    Location:
      -> Device Drivers
        -> Misc devices
```

按搜索结果中的数字键（如 `1`）可以直接跳转到该选项的位置。

**保存配置：**

在 menuconfig 中修改完后：

```
按 → 切换到 Save → Enter → 确认路径为 .config → OK
按 → 切换到 Exit → Enter → 退出
```

**重要：将 .config 同步回 defconfig（否则下次编译会丢失配置）：**

```bash
make ARCH=arm64 savedefconfig
cp defconfig arch/arm64/configs/rockchip_linux_defconfig
```

> `savedefconfig` 会把 `.config` 精简为最小配置集，去掉默认值，只保留用户修改过的选项。

**如果不执行上面两步**，直接 `./build.sh kernel` 也能编译（`.config` 还在），但如果某天执行了 `./build.sh cleanall`，`.config` 会被删除，下次编译又会从旧的 defconfig 生成，你的 menuconfig 修改就丢失了。

#### 总结：两种方式对比

| | defconfig 直接编辑 | menuconfig |
|------|------|------|
| 操作方式 | 文本编辑器改文件 | 终端图形界面 |
| 适合场景 | 明确知道要加什么选项 | 浏览/探索/不确定选项名 |
| 依赖关系 | 需手动处理 | 自动解析 Kconfig 依赖 |
| 同步 | 天然保存在 defconfig | 需手动 `savedefconfig` |

### 3.7 拷贝到开发板并测试

```bash
# 1. 将 beep.ko 推送到开发板（通过 adb / scp / U 盘）
adb push kernel/drivers/misc/beep.ko /tmp/

# 2. 在开发板上加载驱动
insmod /tmp/beep.ko

# 3. 确认驱动加载成功（查看内核日志）
dmesg | tail -5
# 应该看到：misc register succeed
#          GPIO5_DR ioremap ok

# 4. 确认设备节点已创建
ls -l /dev/hello_misc
# 应该看到：crw------- 1 root root 10, xx ... /dev/hello_misc

# 5. 测试设备（写 1 开蜂鸣器，写 0 关蜂鸣器）
echo -ne '\x01' > /dev/hello_misc    # 开
echo -ne '\x00' > /dev/hello_misc    # 关

# 6. 查看驱动 printk 输出
dmesg | tail -3
# 应该看到：kbuf is 1 或 kbuf is 0

# 7. 卸载驱动
rmmod beep
```

## 4. 编译用户态程序并测试

### 4.1 编写用户态测试程序

以 `app_test.c` 为例（配合上面的 beep 驱动）：

```c
#include <stdio.h>
#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <unistd.h>
#include <stdlib.h>

int main(int argc, char *argv[])
{
    int fd;
    char buf[64] = {0};

    fd = open("/dev/hello_misc", O_RDWR);
    if (fd < 0) {
        perror("open error\n");
        return fd;
    }

    buf[0] = atoi(argv[1]);
    write(fd, buf, sizeof(buf));
    printf("buf is %d\n", buf[0]);

    close(fd);
    return 0;
}
```

### 4.2 交叉编译

使用 SDK 自带的 ARM64 交叉编译器：

```bash
# 设置工具链变量
CROSS="/home/whd/experiment/rk3568_linux_5.10_20250211/rk3568_linux_5.10/prebuilts/gcc/linux-x86/aarch64/gcc-arm-10.3-2021.07-x86_64-aarch64-none-linux-gnu/bin/aarch64-none-linux-gnu-"

# 静态链接（推荐，不依赖目标板动态库）
${CROSS}gcc -static -o app_test app_test.c

# 动态链接（体积小，但需要板子有匹配的 libc.so）
${CROSS}gcc -o app_test app_test.c

# 静态 + 去符号（体积最小）
${CROSS}gcc -static -s -o app_test app_test.c
```

### 4.3 验证编译产物

```bash
file app_test
# 应输出：ELF 64-bit LSB executable, ARM aarch64, ...
```

### 4.4 拷贝到开发板并测试

```bash
# 1. 推送可执行文件到开发板
adb push app_test /tmp/

# 2. 在开发板上添加执行权限
chmod +x /tmp/app_test

# 3. 确保 beep 驱动已加载
ls -l /dev/hello_misc

# 4. 运行测试
/tmp/app_test 1     # 开蜂鸣器
/tmp/app_test 0     # 关蜂鸣器
```

## 5. 常见问题

### Q1: `char kbuf[64] = 0;` 编译报错 `invalid initializer`

**原因：** C 语言不能用标量值初始化数组。
**解决：** 改为 `char kbuf[64] = {0};`

### Q2: 清 GPIO 位用 `-(1<<1)` 达不到预期

**原因：** `-` 是算术负号，`-(10b) = 0xFFFFFFFE`；清零特定位需要用按位取反 `~`，`~(10b) = 0xFFFFFFFD`。
**解决：** 清除特定位用 `&= ~(1 << n)`，不是 `&= -(1 << n)`。

### Q3: `LIBRARY_PATH shouldn't contain the current directory`

**原因：** 环境变量 `LIBRARY_PATH` 中包含了 `.`（当前目录），GCC 拒绝编译。
**解决：** 编译前先清除：

```bash
unset LIBRARY_PATH
```

### Q4: 磁盘空间不足

编译需要较大空间。定期清理：

```bash
# 清理 conda 包缓存 (~5.5G)
conda clean -a

# 清理 npm 缓存 (~2.8G)
npm cache clean --force

# 清理 apt 缓存 (~1.1G)
sudo apt clean

# 清理内核编译产物 (~2.6G)
cd kernel && make mrproper
```

### Q5: 板子上 `insmod` 提示 `insmod: can't insert 'beep.ko': invalid module format`

**原因：** `.ko` 编译时使用的内核源码版本与板子运行的内核版本不匹配。
**解决：** 确保用 SDK 中与板子固件对应的内核源码编译，不要混用不同版本的内核树。

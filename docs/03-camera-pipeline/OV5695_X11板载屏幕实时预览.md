# OV5695 在 RK3568 板载屏幕上的 X11 实时预览

## 实现结果

现有 `v4l2_capture` 增加了可选的 X11 预览版本 `v4l2_capture_x11`。程序仍然直接从 RKISP `/dev/video0` 使用 V4L2 multi-planar MMAP 采集 1920×1080 NV12，在板端 CPU 上完成 NV12→RGB 和最近邻缩放，然后送到板端 Xorg `DISPLAY=:0` 的 XFCE 窗口。

这个窗口显示在 RK3568 连接的 1280×800 LVDS 屏幕，不是在 ADB 所在的开发电脑显示。开发电脑只负责通过 ADB 下发启动命令。

## 板端环境

```text
桌面：XFCE
显示服务器：Xorg :0
物理输出：LVDS-1，1280×800@60
采集输入：/dev/video0，1920×1080 NV12
预览窗口：640×360
```

板端已有 GCC、Xlib 开发头文件和 `libX11.so`，因此不需要安装 SDL2 开发包。

## 编译

开发电脑将源码和 Makefile 传到板端：

```bash
adb push ai_doc/tools/v4l2_capture/v4l2_capture.c /tmp/
adb push ai_doc/tools/v4l2_capture/Makefile /tmp/v4l2-preview.Makefile
```

板端原生编译：

```bash
adb shell 'cd /tmp && make -f v4l2-preview.Makefile preview'
```

生成：

```text
/tmp/v4l2_capture_x11
```

## 启动板载屏幕窗口

使用以下命令可从开发电脑启动，但实际窗口属于板端 `DISPLAY=:0`：

```bash
adb shell 'setsid -f env DISPLAY=:0 \
  XAUTHORITY=/var/run/lightdm/root/:0 \
  stdbuf -oL -eL /tmp/v4l2_capture_x11 \
  -d /dev/video0 -W 1920 -H 1080 -p NV12 -b 6 \
  -n 100000000 --preview --preview-size 640x360 -l 300 \
  > /tmp/v4l2-preview.log 2>&1 < /dev/null'
```

窗口标题每秒更新，格式类似：

```text
OV5695 1920x1080 NV12 | FPS 30.05 | frame 434 seq 433 | F/D/R 0/0/0
```

其中 F/D/R 分别代表 forward missing、duplicate、regression。

退出方式：在板载屏幕窗口中按 `Esc`、`Q` 或点击关闭按钮。程序会执行 STREAMOFF、munmap 和 close。也可以在板端终端找到进程后发送 SIGINT。

## 实测结果和性能边界

640×360 窗口实测可保持约 30.05 fps，启动后前 434 帧的 F/D/R 为 0/0/0。X11 窗口树确认窗口尺寸为 640×360，并挂在板端 Xorg 根窗口之下。

960×540 的首版测试只有约 22.45 fps，并出现 sequence forward missing。这是因为当前预览路径使用 CPU 对每个输出像素执行 NV12→RGB，阻塞时间会影响 DQBUF/QBUF 节奏。因此：

- 640×360 用于当前直观调试和实时 FPS 观察。
- 不带 `--preview` 的采集程序继续用于严肃的 V4L2 性能和丢帧基线。
- 后续项目的正式目标仍是 DMA-BUF + DRM/KMS 零拷贝显示，届时不再由 CPU 做全帧颜色转换和拷贝。
